# 환경변수 설정 가이드 (GitHub + Supabase + Vercel)

코드는 하나도 고치지 않아도 돼요. **Supabase에서 값 2개를 복사해서 Vercel에 붙여 넣는 것**이 전부예요.

```
Supabase에서 복사          →   Vercel에 붙여 넣기
─────────────────────────────────────────────────────
Project URL                →   SUPABASE_URL
anon (publishable) 키      →   SUPABASE_ANON_KEY
```

---

## 0단계. GitHub에 올리기

1. GitHub → 오른쪽 위 **+** → **New repository** → 이름 예: `hangul-guardians` → **Private** 추천 → Create
2. **uploading an existing file** 클릭 → 압축을 푼 폴더 안의 파일·폴더를 **전부** 끌어다 놓기 → Commit changes
   - `vercel.json`, `package.json`, `scripts` 폴더도 꼭 함께 올라가야 해요.
   - `.gitignore`, `.env.example` 처럼 점(.)으로 시작하는 파일은 맥에서 안 보일 수 있어요. 없어도 동작해요.

## 1단계. Supabase 준비

> **무료 요금제라 새 프로젝트를 못 만든다면?** 다른 앱에서 쓰던 기존 프로젝트를 그대로 써도 돼요.
> 게임이 만드는 표와 기능은 이름이 전부 `hs_` 로 시작해서(`hs_rooms`, `hs_teams`, `hs_logs` 등) 기존 데이터와 겹치거나 건드리지 않아요.
> 이 경우 아래 1번은 건너뛰고, 기존 프로젝트를 열어 2번부터 하면 돼요. 프로젝트가 **Paused** 상태라면 먼저 **Restore project** 를 눌러 깨워 주세요.

1. [supabase.com](https://supabase.com) → **New project**
   - Region: **Northeast Asia (Seoul)** 추천
   - Database password: 아무 비밀번호 (이 게임에서는 쓰지 않지만 메모해 두기)
2. 프로젝트가 만들어지면(1~2분) 왼쪽 메뉴 **SQL Editor** → **New query**
3. `supabase/schema.sql` 파일 내용을 **전부** 복사해 붙여 넣고 **Run** → 아래에 `Success` 가 뜨면 끝
4. 값 2개 복사하기 — 화면 위쪽 **Connect** 버튼을 누르거나, **Project Settings(톱니바퀴) → API Keys / Data API** 메뉴에서 찾을 수 있어요.

| 복사할 것 | 생김새 | 메모 |
|---|---|---|
| Project URL | `https://abcdefgh.supabase.co` | 끝에 `/rest/v1` 이 붙어 있어도 자동으로 정리돼요 |
| anon public 키 **또는** publishable 키 | `eyJ...` 로 시작하는 긴 글자 또는 `sb_publishable_...` | 둘 중 보이는 것 하나 |

> ⚠️ **`service_role` 키나 `sb_secret_...` 키는 절대 쓰지 마세요.** 학생 화면에 노출되면 누구나 DB를 마음대로 지울 수 있어요. 실수로 넣으면 배포가 자동으로 멈추고 알려 줘요.

## 2단계. Vercel에 환경변수 넣고 배포

1. [vercel.com](https://vercel.com) → GitHub 계정으로 로그인 → **Add New… → Project**
2. 방금 만든 `hangul-guardians` 저장소 옆 **Import**
3. 설정 화면에서 **Environment Variables** 를 펼치고 두 줄 입력

| Key (이름) | Value (값) |
|---|---|
| `SUPABASE_URL` | Supabase에서 복사한 Project URL |
| `SUPABASE_ANON_KEY` | Supabase에서 복사한 anon / publishable 키 |

   - 이름은 **대문자·밑줄까지 정확히** 똑같이 써야 해요. 복사해서 붙여 넣는 걸 추천해요.
   - 값 앞뒤에 따옴표(`"`)나 공백을 넣지 마세요.
   - Framework Preset 등 나머지 설정은 그대로 두세요. (`vercel.json` 이 알아서 처리해요)
4. **Deploy** → 1분 안에 완료

## 3단계. 잘 됐는지 확인

1. 배포된 주소 뒤에 `/teacher.html` 을 붙여 접속
2. 첫 화면 맨 아래 문구 확인

| 보이는 문구 | 뜻 | 할 일 |
|---|---|---|
| 🟢 Supabase 연결 설정됨 | 성공! | 「방 만들기」로 시험해 보기 |
| 🟡 로컬 테스트 모드예요 | 환경변수가 안 들어감 | 아래 「값을 바꿨을 때」 참고 |
| 🔴 데이터베이스 표가 없어요 | schema.sql 을 실행 안 함 | 1단계 2~3번 다시 |
| 🔴 API 키가 맞지 않아요 | 키를 잘못 복사함 | 키 다시 복사 → 환경변수 수정 → Redeploy |

3. 아이패드나 휴대폰으로 학생 주소에 접속해 방 코드로 들어가 보고, 선생님 화면 모둠 카드에 이름이 뜨면 완벽해요.

## 값을 바꿨을 때 (가장 많이 하는 실수!)

환경변수는 **새로 배포할 때만** 반영돼요. 값을 넣거나 고친 다음에는 꼭:

**Vercel 프로젝트 → Deployments → 맨 위 배포 오른쪽 `⋯` → Redeploy**

배포 기록(Build Logs)에 `✅ Supabase 연결 설정 완료` 가 보이면 제대로 들어간 거예요.
`⚠️ Supabase 환경변수가 비어 있어요` 가 보이면 이름 철자를 다시 확인해 주세요.

## 참고

- **Vercel의 Supabase 연동(Integrations → Supabase)** 으로 연결했다면 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` 가 자동으로 생기는데, 이 이름도 그대로 인식해요. 따로 넣지 않아도 돼요.
- 키는 GitHub에 올라가지 않고 Vercel에만 저장돼요. 저장소의 `js/config.js` 는 빈 채로 두면 돼요.
- 무료 요금제로 충분해요. 다만 Supabase 무료 프로젝트는 일주일 넘게 안 쓰면 **일시 중지(Paused)** 될 수 있어요. 수업 하루 전에 Supabase 대시보드에 들어가 보고, 중지돼 있으면 **Restore project** 를 눌러 깨워 두세요. 선생님 화면에서 방을 하나 만들어 보는 것까지 해 두면 안심이에요.
